# Scrum Híbrido - Operating Model IRIS

## Contexto de equipo

- Equipo total: 4 personas.
- Responsabilidades compartidas.
- Facilitación principal: rol Scrum Manager liderado por ti.

## Sprint y capacidad

- Duración sprint: `1 semana`.
- Capacidad reservada para fast lane: `20-25%`.
- Capacidad objetivo sprint lane: `75-80%`.

## Ceremonias semanales

- `Sprint Planning` (lunes, 60-90 min)
  - Definir sprint goal.
  - Cerrar compromiso de historias.
- `Daily` (15 min)
  - Foco en bloqueos y coordinación.
- `Sprint Review` (viernes, 45 min)
  - Demostración de valor entregado.
- `Retrospective` (viernes, 45 min)
  - Mejoras concretas para siguiente sprint.

## WIP Limits sugeridos

- `In Progress`: máximo 3 items.
- `In Review`: máximo 2 items.
- `Ready`: sin límite duro, pero priorizado.

## Política de urgencias (Fast lane)

- Solo entran:
  - Bugs bloqueantes.
  - Incidencias de alta prioridad validadas por facilitación.
- Si una urgencia rompe capacidad:
  - Registrar impacto en sprint review.
  - Replanificar scope explícitamente.

## Definition of Ready (DoR)

Antes de entrar en sprint:

- Historia comprendida por el equipo.
- Criterios de aceptación explícitos.
- Dependencias identificadas.
- Estimación completada.

## Definition of Done (DoD)

Para mover a `Done`:

- Código implementado y revisado.
- PR mergeada.
- Validación funcional mínima en desktop y mobile (si aplica).
- Issue enlazada con evidencia.
- Documentación actualizada si hubo cambio funcional/técnico.

## Métricas mínimas

- Sprint goal hit rate.
- Cycle time promedio.
- Bugs abiertos/cerrados por sprint.
- Throughput semanal.

## RACI ligero por ceremonia

| Ceremonia | Responsable | Participantes | Salida |
|---|---|---|---|
| Planning | Scrum Facilitator | Todo el equipo | Sprint backlog + goal |
| Daily | Rotativo | Todo el equipo | Bloqueos y ajustes |
| Review | Scrum Facilitator | Equipo + stakeholders | Validación de valor |
| Retro | Scrum Facilitator | Todo el equipo | 1-2 acciones de mejora |
